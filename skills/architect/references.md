# Architecture Skill References

This file records source attribution; load it only when sources or provenance matter. The skill's guidance is an original synthesis, and does not adopt every source's framing as a universal rule.

## Terminology and patterns

- [Michael Feathers, *Working Effectively with Legacy Code*](https://www.informit.com/store/working-effectively-with-legacy-code-9780131177055), ch. 4—seams.
- [Martin Fowler, *Patterns of Enterprise Application Architecture*](https://martinfowler.com/books/eaa.html)—Service Layer, Domain Model, and Gateway patterns.
- [Frank Buschmann et al., *Pattern-Oriented Software Architecture, Volume 1*](https://www.wiley.com/en-us/Pattern+Oriented+Software+Architecture%2C+Volume+1%3A+A+System+of+Patterns-p-9780471958697)—Pipes and Filters.
- [Connascence reference](https://connascence.io/)—coupling vocabulary and the strength, degree, and locality axes.
- [John Ousterhout, *A Philosophy of Software Design*](https://web.stanford.edu/~ouster/cgi-bin/book.php)—deep modules and the original depth framing; this skill uses depth-as-leverage rather than a line-count ratio.
- [Eric Evans, *Domain-Driven Design* and DDD Reference](https://www.domainlanguage.com/ddd/)—bounded contexts, domain models, and layered architecture.

## Review and documentation aids

- [Karl Wiegers and Joy Beatty, *Software Requirements*, 3rd ed.](https://www.microsoftpressstore.com/store/software-requirements-9780735679665)—`requirements.md`: detail calibration (ch. 11) and vision-and-scope sections (ch. 5); `diagrams.md`: diagram selection (ch. 12), adapted for current notations.
- [Steve McConnell, *Code Complete*, 2nd ed.](https://www.microsoftpressstore.com/store/code-complete-9780735619678)—`architecture-review.md` (ch. 3) and `module-review.md` (ch. 5).

Named patterns, checklists, and interpretations in the skill are selective adaptations; use them as decision aids, not mandatory frameworks.
